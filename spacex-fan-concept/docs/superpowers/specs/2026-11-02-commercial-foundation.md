# Commercial foundation: phase 1

User authorization: continue all previously recommended commercialization improvements and start implementation. Preserve the approved SpaceX viewer, source-only geometry and Git-to-Vercel publication.

Chosen approach (implementation decision): incremental productization, not a visual redesign or full framework rewrite. Introduce a vendor-neutral session adapter and allowlisted embedding protocol; keep the SpaceX catalog as the first content pack. Add keyboard inspection and an HTML-only catalog, automated asset/license/bundle checks and a commercial readiness dossier. The platform is still a prototype, not certified engineering software or a fully generic renderer.

Alternatives: selling the branded demo as exclusive IP is not suitable because it contains third-party models, fonts and marks. Rewriting the renderer as a full SDK now risks approved interaction/visual behavior; defer deeper renderer extraction until a second content pack is validated.

Non-goals: sending outreach or proposals, purchasing assets or domains, changing the approved art direction, manufacturing internal geometry, claiming physical-device tests, assigning unverified IP or writing a binding contract.

Completion evidence: existing regression tests; new unit tests for neutral API/authentication, data budgets and artifact checks; actual keyboard and automated accessibility checks; static no-JS catalog; compiled build with source provenance and package notices; measured lab report that distinguishes bytes and software-rendered timings from physical GPU performance. Publication must match tested source hashes.
