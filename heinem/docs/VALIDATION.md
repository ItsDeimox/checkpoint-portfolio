# Validation — HEINEM

The current **v1.1 meadow/CD revision** has a separate [validation record](VALIDATION-1.1.md), [approved concept and decisions](MEADOW-REVISION.md), and desktop/mobile evidence. The following record preserves the **v1.0.0 historical baseline**; its deployment IDs and bundle sizes are not presented as v1.1 results.

## Historical baseline — 1.0.0

Verification date: **2026-10-22 UTC**. Evidence distinguishes the actual application, simulated provider events and an external service's behavior. It is not a claim of universal device performance.

## Reproducible checks

```bash
npm ci
npm run build
npx playwright install chromium
npm run test:e2e
```

The build runs `npm run check` (TypeScript plus the nine policy tests) before Vite. The browser suite remains a separate integration check.

`CHROMIUM_PATH` selects an already installed compatible browser. `PLAYWRIGHT_BASE_URL` points the browser suite at a deployment instead of the local server. The suite is in `tests/browser/site.spec.ts`; quality policy tests are in `tests/quality.test.ts`.

The local environment used Node 24, Vite 8.3.5, TypeScript 7.0.2 and Linux Chromium 134 with ANGLE/SwiftShader. These are **software GPU tests**, not physical-phone or physical-GPU frame-rate measurements. The Playwright runner is version 1.64.1; its `CHROMIUM_PATH` override was used because the current default browser download was unavailable in this environment.

## Real SoundCloud check and its limit

The real SDK and official player were exercised separately from the deterministic mock tests. Chromium initially rejected this environment's TLS certificate chain. The SDK returned HTTP 200 through `curl` with normal TLS verification. A second disposable browser context used an explicit test-only TLS exception; no production setting or system certificate was changed.

In that context, SDK, iframe, track resolution and waveform returned HTTP 200. Real `READY` and duration **228232 ms** arrived for *Memories Of You*. The first attempt exposed a missing `encrypted-media` delegation. The application now uses `allow="autoplay; encrypted-media"`, consistent with the fix recorded in [SoundCloud's official issue #535](https://github.com/soundcloud/api/issues/535).

After that correction, the permission violation disappeared, but this Chromium still received `PLAY → PAUSE` at position zero, with no `PLAY_PROGRESS`. One direct click on the official player's button also did not start a stream. Continuous audio playback therefore **was not confirmed in this environment**. The remaining cause was not identified; it is not represented as a successful listening test. The CD follows the real pause event and shows a useful message with the official player and verified track link available.

Browser policy, provider availability and territorial or track restrictions remain external dependencies. Audio is not downloaded or re-hosted by the application.

## Practical limits

The original art was a flattened screenshot. Hidden scenery was reconstructed, the logo is an SVG interpretation, and mobile is deliberately recomposed. These are documented limits to a literal pixel-identical claim. Performance budgets are bounded in code, but no Lighthouse score, Core Web Vitals field result, battery figure or physical-device FPS is invented. A future hardware pass should record device, browser, refresh rate, selected profile, temperature and actual presented frames.
