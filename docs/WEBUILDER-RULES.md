# Webuilder: regras operacionais para IA

Estas regras valem para o projeto ChatGPT **Webuilder** e para agentes que desenvolvem seus sites. Aplicam-se a trabalhos explicitamente solicitados pelo usuário, respeitando permissões, limites técnicos e segurança.

1. **Executar imediatamente.** Quando a solicitação for direta e já trouxer informação suficiente, começar a implementação usando as ferramentas disponíveis. Não substituir a execução por frases como “vou fazer assim”, planos genéricos, brainstorms, perguntas repetidas ou pedidos de confirmação desnecessários. Comunicar resultados e bloqueios concretos; atualizações de progresso apenas durante execução real.
2. **GitHub é a fonte da verdade.** Alterações de código, recursos, testes e documentação entram no repositório correto, em commits rastreáveis e sem sobrescrever trabalhos alheios. Consultar a branch e o histórico atual antes de editar; preservar áreas já aprovadas e modificar somente o escopo solicitado.
3. **Vercel por integração Git.** Para projetos Vercel vinculados ao GitHub, como `ItsDeimox/checkpoint-portfolio/heinem`, o fluxo padrão e obrigatório é **editar → validar → commit/push no GitHub → deploy automático pela integração Git da Vercel → verificar SHA/estado/domínio**. Não criar uploads ou deploys manuais paralelos pela API/CLI da Vercel em atualizações comuns. Um deploy manual só entra por autorização explícita ou recuperação de falha comprovada da integração, respeitando a intenção do usuário e os limites da plataforma.
4. **Não confundir commit com publicação.** Confirmar build e testes, o SHA exato servido, estado READY e alias público. Se o deploy estiver bloqueado, com quota excedida ou falhar, relatar claramente que somente o commit foi realizado; não dizer que o site foi atualizado.
5. **Fidelidade e performance.** Seguir a referência visual aprovada sem redesenhar outras seções. Reutilizar arquitetura e técnicas comprovadas do Checkpoint e do Cortex, com shaders e efeitos dimensionados por dispositivo, fallback, acessibilidade, responsividade, pausas quando invisível e respeito ao movimento reduzido.
6. **Verificar e registrar.** Sempre que viável, validar build, testes, interações de mouse/touch, mobile e site público; documentar decisões, mudanças, problemas e limitações nos repositórios pertinentes, inclusive Cortex quando surgir técnica reutilizável.
7. **Sem fingir capacidades.** Agentes devem usar ações realmente autorizadas e disponíveis. Não alegar ter alterado as instruções internas do Projeto do ChatGPT se não houver uma ferramenta ou permissão específica para modificá-las. Este arquivo é um espelho versionado da regra, não substitui por si só as instruções salvas nas configurações do Projeto.

**Exceção importante:** o aplicativo desktop Checkpoint Portfolio também publica GitHub Pages; esta regra não converte esse fluxo em Vercel. Aplicar o provedor configurado em cada aplicação.
